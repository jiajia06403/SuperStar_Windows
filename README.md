# SuperStar · 学习通自动刷课（Windows 桌面版）

超星学习通 Windows 桌面客户端。绿色解压即用，无需浏览器、无需 Python 环境。

> ⚠️ 本项目仅供学习交流，请勿用于商业用途；使用产生的后果由使用者自行承担。

---

## 功能

### 为什么用它

| 对比项 | 常见的同类方案 | SuperStar Windows |
| --- | --- | --- |
| 运行方式 | 油猴脚本 / 浏览器插件，**必须一直开着浏览器标签页** | 桌面客户端，纯 HTTP 直连平台接口，**全程不需要浏览器参与** |
| 浏览器自动化 | 部分方案依赖 Selenium / Playwright，需另装 Chrome 与对应驱动，版本稍不对就崩 | 不引入任何浏览器自动化组件，无 WebDriver、无驱动版本问题 |
| 环境要求 | 需自备 Python + 依赖，或需装浏览器扩展 | 发行包解压即用，**不需要 Python 环境**，也不需要在浏览器里装任何东西 |
| 登录态 | 依赖网页端保持登录，换个浏览器/清 Cookie 就失效 | 客户端内登录（密码 DPAPI 加密保存）或可选 cookies 登录，与浏览器无关 |
| 界面 | 控制台 / 网页脚本，参数靠改配置文件 | 原生桌面 GUI（tkinter/ttk 标准库），课程勾选、倍速并发、章节状态、日志一屏可见 |
| 体积 | Electron 类壳动辄上百 MB | 单 exe 约 28MB，常驻内存约 70MB |
| 多账号 | 基本不支持 | 多账号保存与切换，进度按账号 uid 隔离缓存 |

### 功能清单

- **不需要浏览器参与**：网络层全部走 `requests` 直连超星接口（登录、章节、视频、文档、作业、直播、题库），
  不启动浏览器、不注入脚本、不依赖页面元素结构，前端改版不影响本机使用。
- **进度以服务端为准**：章节是否完成一律看平台返回的「已完成」，本地缓存只做辅助记录；
  平台要求重新作答（判分不合格 / 未提交）的章节会被自动清除本地完成标记并重新处理。
- **按账号 uid 缓存进度**：`progress_cache/<uid>.json`，格式 `{courseId: {pointId: true}}`，多账号互不干扰。
- **账号自动登录**：勾选「记住账号与密码」后写入 `progress_cache/accounts.json`，
  密码用 Windows DPAPI 以当前用户身份加密（换机器/换用户无法解密）；下次启动自动登录。
  取消勾选则只记住手机号，登录框自动回填。
- **账号切换**：下拉选择已登录账号（显示手机号 + uid），切换时同步切换进度缓存。
- **读取进度**：一键调用服务端接口，用真实完成状态**双向对齐**本地缓存（完成则标记、未完成则清除）；
  同时逐章探测章节是否开放，未开放的章节在列表里显示「未开放」而不是「待学」。
  整个过程异步进行：先出完成状态，再逐行点亮「未开放」，界面不卡；期间按钮禁用，切课程/开始刷课会中断探测。
- **答题不合格自动重答**：章节检测提交后回读任务点，平台仍判未通过则重新作答，
  单次刷课内的次数由 `config_win.ini` 的 `[tiku] work_retry` 控制（默认 3，0 表示不重答）；
  重答后仍不合格的章节保留「未完成」，不计入已完成。
- **未开放章节智能处理**：先回退检查上一章是否未完成并重做，再回到当前章验证是否解锁；
  **若上一章因答题不合格而一直不通过（当前章永远解不了锁），重答不设上限**，
  每 5 秒再来一轮，直到平台判通过或用户点停止；上一章已完成则每 15 秒轮询当前章，直到开放或用户停止。
- **视频状态日志**：观看视频时每 N 秒在日志输出一条进度
  （章节号 + 章节名 / 视频名 / 进度百分比 / 已播与总时长 / 倍速 / 预计剩余时间），
  便于判断是否卡住；间隔由 `config_win.ini` 的 `[common] video_log_interval` 控制（默认 30 秒，0 = 关闭），
  界面「设置」里也能改，刷课过程中改动立即生效。
- **界面主题（Win11 观感）**：浅色 / 深色 / **跟随系统**三档，在「设置 → 外观」里切换，
  也可改 `[ui] theme`（`system` / `light` / `dark`）。跟随系统时轮询注册表
  `AppsUseLightTheme`，Windows 一改深浅色界面自动重刷；标题栏走 DWM
  沉浸式深色 + Win11 圆角。深色下章节状态色、日志告警色成套替换（原深绿/深红在
  深底上不可读）。工具栏在窄窗口/高 DPI 缩放下自动折成两行，不再裁掉右侧按钮。
- **本地题库（只存正确答案）**：作业提交成功后向平台核验，**判对**的答案入库、
  **判错但页面给了正确答案的，把正确答案入库**；库里已有的答案若与平台给出的正确答案
  不一致（典型场景：用题库答案作答却被判错），会被**覆写纠正**。重做同一份作业、
  或用另一个账号做同一门课时优先命中，不再消耗题库/大模型额度。题库**按课程一个文件、
  全账号共享**（`progress_cache/local_bank/<课程ID>.json`），只写「库里没有」或
  「和平台不一致」的题，按选项文本重映射，选项乱序也能对上；支持导出/导入/合并共享。
  可在配置里一键停用。
- **已完成账号批量采集**：主界面「采集题库」把历史作业的成绩页读一遍（只发 GET、不提交），
  把正确答案 / 我的答案批量导进本地题库，换账号做同一门课直接命中。
- **演示模式（仅源码/测试，不随发行包）**：内置假后端，无需账号/网络即可跑通全流程。

## 使用说明

1. 解压发行包，双击 `SuperStar.exe`（无需安装）；
2. 点「添加账号」登录（或勾选 cookies 登录）；
3. 左侧点击课程名勾选要刷的课程，可「全选」；
4. 设置倍速/并发（默认 2.0 倍速 / 4 并发），点「开始刷课」；右侧看章节状态，底部看日志，状态栏显示当前章节进度；
   这两项会写进 `config_user.ini` 的 `[common] speed / jobs`，下次启动自动恢复上次的取值
   （范围 1.0~2.0 倍速 / 1~8 并发，超出范围会按边界值纠正）；
5. 「读取进度」用服务端真实进度刷新缓存；「刷新列表/刷新章节」重新拉取课程与章节；
6. 需要自动答题：点工具栏「设置」，在「答案提供方式」下拉中选（言溪 / LIKE / TikuAdapter / AI / DeepSeek / SiliconFlow），
   下方只会显示该方式需要的项（TOKEN、服务地址，或接口地址 + API Key + 模型）；
   大模型三种方式各存各的配置，切换时会带出各自的默认地址与模型，只需补 API Key。也可手改 `config_user.ini`。
7. 想看视频进度：同一「设置」窗口的「视频日志」里填间隔秒数（默认 30，0 = 不输出），
   刷课时日志会出现形如 `视频进度 | 章节 3/12《第二章 导数与微分》| 任务 1.1 导数的定义 | 45.2% (812/1800s) | 2x | 剩余约8分14秒` 的行。

## 分发形态：整个文件夹，不是单个 exe

运行期需要的条目**全部随压缩包分发**：

| 条目 | 作用 |
| --- | --- |
| `SuperStar.exe` | 主程序（文件名不带版本号，版本体现在压缩包名上） |
| `runtime/` | 程序运行时文件（Python 运行时 / 依赖库 / 内嵌资源，**exe 启动必需，勿删**） |
| `config_win.ini` | 默认配置（随包自带，升级时被覆盖，用户不要改） |
| `config_user.ini` | 用户配置（首次启动自动生成，升级不覆盖） |
| `chaoxing.log` | 运行日志（首次启动自动创建，追加写入；不随包，不会在升级时清空旧日志） |
| `progress_cache/` | 进度缓存 / 账号 / cookies / 题库答案缓存 / **本地题库**（`local_bank/<课程ID>.json`），首次启动自动创建 |
| `使用说明.txt` | 随包说明 |
| `LICENSE` | GPL-3.0 许可文本（二进制分发必须随附） |

设计约束：

- **用 PyInstaller onedir（不是 onefile）**：onefile 每次启动都要把上千个文件解压到 `%TEMP%`，
  换机首次运行时这批新文件还要被杀毒软件逐个扫描 —— 这是「首次启动要好几秒」的主因；
  onedir 直接就地加载，免掉解包与首轮全量扫描。代价是不能只拷一个 exe
  （只拷 exe 会报 `Failed to load Python DLL`）；
- `runtime/` 必须与 exe **平铺同级**（bootloader 只在 exe 同级找运行时目录）；
- 运行期所有写入都收进上述位置（`paths.py` 统一解析），exe 目录顶层只多出 `config_user.ini`；
- `config_win.ini` 不内嵌进 exe，只由压缩包随附；
- 压缩包内**不套顶层目录**（解压即得主目录），zip 名即默认解压文件夹名；
- 升级建议先删旧文件夹再解压新包（避免旧文件残留）；
- 程序本身不做文件校验、不弹窗、不阻断启动，注意事项写在 `使用说明.txt`。

## AI 使用情况

**产品内的 AI 能力（可选，默认停用）**

| 环节 | 说明 |
| --- | --- |
| 题库提供方 | `[tiku] provider` 可选 `TikuYanxi`（言溪）、`TikuLike`（LIKE 知识库）、`TikuAdapter`（自建）、`AI`（任意 OpenAI 兼容端点）、`DeepSeek`（官方）、`SiliconFlow`（硅基流动）；界面下拉切换后只显示该提供方需要填的项 |
| 用途 | 仅用于回答章节检测 / 作业的选择、填空、判断、简答题；视频、文档、阅读等非作答任务点不走 AI |
| 调用方式 | 题目 + 选项拼成 prompt，要求模型以 `{"Answer": [...]}` JSON 输出，按题型校验后才写入答案缓存 |
| 开关与降级 | 未填 API Key 即停用题库，跳过答题；`openai` / `httpx` 为惰性导入的可选依赖，缺失只影响大模型类提供方，其余题库与刷课照常 |
| 数据范围 | 请求只含题目文本，不含账号、Cookie、学校等身份信息；题目与答案会落到 `progress_cache/cache.json` 本地缓存 |
| 频率控制 | `min_interval_seconds` 限制请求间隔，避免触发限流 |

**开发过程中的 AI 参与**

- 界面、引擎、构建脚本与文档在 AI 编程助手辅助下编写与迭代（代码经人工审阅、自检与冒烟测试后合入）。
- 本仓库不包含任何 AI 生成但未经验证的逻辑：所有功能均通过 `test/` 下的单测与冒烟测试，
  界面行为由 `python run.py --selftest` 断言。

## 配置：默认配置 + 用户配置（防覆盖）

升级时用户会把新压缩包解压覆盖到旧目录，因此配置拆成两份：

| 文件 | 来源 | 升级时 | 用户是否可改 |
| --- | --- | --- | --- |
| `config_win.ini` | 随包分发 | **被覆盖** | 不要改（改了也会丢） |
| `config_user.ini` | 首次启动按默认配置生成 | **不覆盖** | 改这里 |

规则（`config_store.py` 实现）：

- **读取**：默认配置打底，用户配置逐键覆盖；用户显式留空也算覆盖（可用于停用题库）；
- **迁移**：每次启动用最新的默认配置校验用户配置
  - 新增键 → 以默认值补进用户配置；
  - 已删除的键 → 从原段移除，值保留到 `[obsolete]` 段（不生效、不丢数据）；
  - 取值非法（如 `cover_rate=abc`、`submit=yes`）→ 回落默认值，日志里写明原值；
- **写入**：只写用户配置，且走文本级最小改动（保留用户注释），迁移幂等。

## 本地题库：只存正确答案，按课程共享，重做/换账号直接读

同一门课的题目和答案对所有账号都一样，所以题库**按课程存放、全账号共用**：
换账号做同一门课直接命中，不用重复采集，也不再消耗题库或大模型额度。

工作方式：

1. 作业**真正提交**成功后，重新拉取一次作答页，解析每题的对错与「正确答案」；
2. 判对 -> 收录本次答案（它就是正确答案）；判错但页面给出「正确答案」-> 收录正确答案；
3. 判错且拿不到正确答案、或页面还没批阅 -> **不收录**（题库里只有正确答案，绝不猜）；
4. **只同步缺的题**：题库里已经有正确答案的题直接跳过，重复做同一份作业、多人共用同一份
   题库都不会重复写入或改写历史答案；如果整份作业的题都已有答案，连核验请求都不再发；
5. 搜题时**最先**查本地题库，命中就直接用，未命中才走题库/大模型；
6. 指纹 = 归一化标题 + 题型 + 归一化选项（去题号、分值、`【单选题】` 标签，选项排序），
   所以换账号、换章节、同一题出现在不同作业里都能命中；
7. 入库时还会保存答案对应的**选项文本**；选项顺序变了就按文本重新映射字母。
   选项文字对不上（题干被改写）时宁可不答，也不提交必然错的答案。

存储结构（一门课一个文件，不按账号分文件夹）：

```
progress_cache/local_bank/
    高等数学_246831735.json
    大学英语_247100002.json
```

查询顺序：当前课程文件 -> 其它课程文件（同一道题被多门课复用时也能命中）。
旧结构会在启动时自动迁移：初版单文件 `local_bank.json` 和上一版的
`<账号>/<课程>.json` 都会合并进课程文件，旧目录**改名**为 `.migrated` 保留，不删数据；
上一版命名 `<课程标题>_<课程ID>.json` 会在启动时自动改名为 `<课程ID>.json`（已存在则合并）。

| 操作 | 位置 / 命令 |
| --- | --- |
| 存储 | `progress_cache/local_bank/<课程ID>.json`（`[tiku] local_bank_dir` 可改根目录） |
| 界面 | 设置 →「本地题库…」：查看统计、导出、导入合并、打开目录、清空 |
| 采集 | 主界面「采集题库」按钮，或 `python -m api.collect --course 关键词` |
| 命令行 | `python -m api.local_bank stats` / `list` / `export out.json` / `import in.json` / `merge a.json b.json -o 目录` |

导出是一个 JSON 包（按课程分文件），导入时按原结构还原；导入即合并：
同题答案相同时累加「确认次数」，不同则保留确认次数更多的那个。
所以一份题库可以多人共用，越用越准。

开关（写在 `config_user.ini` 的 `[tiku]` 段，改完重启或保存一次设置即生效）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `local_bank` | `true` | 总开关；`false` 完全不读不写（文件保留） |
| `local_bank_verify` | `true` | 提交后核验并补录缺失的正确答案；`false` = 题库只读不写 |
| `local_bank_dir` | 空 | 题库根目录，留空 = `progress_cache/local_bank` |

> 判分页结构变化导致核验认不出时，本地题库会**跳过收录**而不是乱收（日志会写明）。
> 老配置里的 `local_bank_trust`（收录未核验答案）已移除：题库只存正确答案，
> 这条宽松路径不再存在；升级时该键会自动移入 `[obsolete]`。

### 从已完成账号批量采集（不用重做作业）

已经刷完课（或已有高年级账号）的课程，作业页就是成绩页——里面写着每题对错、「正确答案」
和「我的答案」。主界面点 **采集题库**（或命令行 `python -m api.collect`）会把这门课所有
作业读一遍，一次性攒出题库，**只发 GET，不提交、不保存草稿**。

| 页面情况 | 收录什么 |
| --- | --- |
| 给了「正确答案」 | 正确答案（最权威，判错也照收） |
| 判对但没公布答案 | 页面上的「我的答案」（已被平台判对） |
| 判错且没有正确答案 | 跳过（不知道对的是什么，不猜） |
| 作业还没提交过 | 跳过，计入「未提交」（页面上只有作答区，没有答案可采） |
| 已提交但未批阅 / 未公布答案 | 跳过，计入「未批阅」 |
| 页面改版认不出 | 跳过并计入「无法识别」，原始页面存到 `progress_cache/collect_debug/`（报问题时发这个文件） |
| 题库里已有答案且与页面一致 | 跳过（不重复写） |
| 题库里已有答案但与页面不一致 | 覆写纠正（页面答案为准） |

用法：

- 界面：勾选课程 → 「采集题库」→ 确认 → 后台跑，日志里逐章显示进度，`停止` 可中断
  （已采集的部分保留，不必从头再来）；
- 命令行：`python -m api.collect`（全部课程）、`--course 高等数学,247100002`（按标题关键词
  或 courseId 过滤）、`--max-works 3`（只读 3 份作业试跑）、`--uid <uid>`（指定已保存账号）。
  命令行复用本机已保存的账号密码（DPAPI 加密），所以要先在界面登录过一次。

采集结果落在**课程文件**：`local_bank/<课程ID>.json`，所有账号共用。所以拿一个已刷完的老账号
采集一轮，新账号做同一门课时就能直接用它；再采一次只写新题和与页面不一致的题，
不会重复写入。

> 请求量约为「章节数 × 1 次卡片 + 每份作业 1 次」，一门几十章的课需要几分钟；
> 采集走刷课同一套限速器，不会把请求打爆。

## 构建与分发

**版本号唯一来源：仓库根目录 `version.txt`**：zip 名、Release 标题全部原样取它的内容
（`1.0.0` 就出 `SuperStar-1.0.0-win64.zip`，`1.0.0-rc.1` 就出 `SuperStar-1.0.0-rc.1-win64.zip`）。
**exe 文件名恒为 `SuperStar.exe`（不带版本号）**，版本区分由压缩包名承担。
发新版 = 改 `version.txt` → 打成 tag 推上去（惯例 `v<版本>`），Release 由 CI 产出。

```bash
python -m pip install pyinstaller
python build.py              # dist/ 铺成安装目录 + dist/SuperStar-<版本>-win64.zip（exe 恒为 SuperStar.exe）
python build.py --clean      # 清理后重建
python build.py --exe-only   # 只出 onedir 产物目录（build/onedir/SuperStar/），不铺装不打 zip
```

`python build.py` 做两件事：

1. **铺装 `dist/`**：exe + `runtime/` + 随包文件 —— `dist/` 即用户解压后看到的文件夹，可直接双击验证；
2. **打 zip**：同等内容（含 `LICENSE`）直接放在 zip 根，解压即得主目录。

产物**不含演示模式**：构建时 `--exclude-module demo_chaoxing gui.selftest`，
`gui.app.demo_available()` 导入失败即隐藏「演示」按钮，`--demo` / `--selftest` 以退出码 3 拒绝。

```bash
python run.py --selftest   # 源码态界面自检，退出码 0 = 通过
python run.py --demo       # 源码态演示模式
dist/SuperStar/SuperStar.exe --selftest   # 退出码 3：证明发行包已无演示能力
```

## 测试

测试按耗时与依赖分三层，**默认只跑 core**（日常改完跑这个即可）：

| 层 | 内容 | 命令 | 参考耗时 |
| --- | --- | --- | --- |
| `core` | 纯逻辑单测，无窗口 / 无网络 | `python test/run_test.py` | ~45s |
| `gui` | 真实 Tk 窗口（界面冒烟、设置窗、倍速并发、主题切换） | `python test/run_test.py --gui` | ~30s |
| `slow` | 日志文案、构建产物与版本号约定 | `python test/run_test.py --slow` | ~15s |

```bash
python test/run_test.py              # core（默认）
python test/run_test.py --all        # 全量：core + gui + slow
python test/run_test.py --all --dist # 追加校验发行 exe 拒绝 --selftest（退出码 3）
python test/run_test.py --list       # 只看分层清单
```

分层靠每个测试文件首行的 `# layer: core|gui|slow` 标记，**新增测试缺省进 core**，不会漏跑。

`gui` 层要真窗口：当前解释器没有 tkinter 时自动回落到 `.venv-build/Scripts/python.exe`，
两者都没有则明确 SKIP 而不是报失败。

`test_gui_smoke.py` 校验：课程/章节渲染、章节状态全部更新为「完成」、日志非空、
开始按钮恢复可用、布局未被窗口裁切。

> 一次性调试脚本归档在 `test/archive/`（说明见其中 `README.md`），不参与上述调度器。
> 测试依赖仓库内的 `demo_chaoxing.py`，只能在源码目录运行，**也不在 CI 中执行**
> （CI 只做构建与发行包基本校验，保持构建快速）。

## 发布 Release（GitHub Actions）

`.github/workflows/release.yml` 两条触发路径：

| 触发 | 条件 |
| --- | --- |
| 发版 | 推 tag `v<版本>`（惯例与 `version.txt` 一致：`$v=(Get-Content version.txt).Trim(); git tag "v$v"; git push origin "v$v"`） |
| 试构建 | Actions → Release → Run workflow（只出 Artifact，不发 Release） |

产物名只认 `version.txt`：写 `1.0.0-rc.1`，zip 就是 `SuperStar-1.0.0-rc.1-win64.zip`。
CI 不做版本号格式校验、不校验 tag 与 `version.txt`、也不区分正式版/预览版
（`prerelease` 标记与预览版提示已全部移除）。

流程（两个 job）：

1. **Build Windows executable**（windows-latest）：装依赖 → 读 `version.txt` →
   `python build.py` → 确认 exe / zip 产出 → `upload-artifact` 上传 zip；
2. **Publish GitHub Release**（ubuntu-latest）：取 tag 版本号 → 下载 Artifact →
   用「上一个 tag 至今的提交」生成 changelog → 创建 Release 并上传 zip（不单独上传裸 exe）。

> CI 不跑测试套件：`test_gui_smoke` 要建真实窗口，在 runner 上慢且易受环境影响，
> 该部分只在本地 `python test/run_test.py` 执行；
> zip 内容由 `build.py` 铺装逻辑保证，也不在 CI 里逐条校验。

## 已知限制

- 真实账号登录与刷课依赖超星服务端，需在自有 Windows 环境实跑确认；仓库内验证基于演示后端。
- 题库默认停用；`provider=AI` / `DeepSeek` / `SiliconFlow` 需自备 API Key，答案准确性由模型决定，不保证判分通过。
- `--selftest` 只验证界面与引擎接线，不替代真实刷课验证。
- 本地题库的自动收录依赖「提交后页面能读出对错」：平台尚未批阅、或判分页改版时不会收录
  （只影响入库，不影响答题）；判错但页面给了「正确答案」时也会把正确答案收录（纠错）。
  需要「不管对错先存下来」时才把 `local_bank_trust` 设为 `true`。
- 采集题库只对**已提交**的作业有效：没交过的作业页只有作答区，没有对错和答案可采
  （日志里记为「未提交」）。所以先去刷课（刷课会提交章节测验）或自己交一遍，再采集。
  教师关闭「查看答案」、作业未批阅时读不到答案，只会计入「未批阅」并跳过（不影响答题与已有题库）；
  页面结构改版认不出时会把原始 HTML 存到 `progress_cache/collect_debug/`，
  日志里给出路径，反馈问题时发那个文件即可。
